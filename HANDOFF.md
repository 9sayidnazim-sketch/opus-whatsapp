## 2. Browser Web Push Notifications Architecture
Engineered per the user request for native browser push notification capability:
- **Service Worker (`public/sw.js`):**
  - Handles `push` events with JSON/text payload parsing, custom icons (`/favicon.svg`), vibration pattern `[100, 50, 100]`, and action buttons ("Open Ledger", "Dismiss").
  - Handles `notificationclick` events with multi-window routing and tab focusing.
- **Notification Utility Module (`src/utils/notifications.js`):**
  - `isNotificationSupported()`: Browser feature detection.
  - `getNotificationPermission()`: State detection (`default` | `granted` | `denied`).
  - `registerServiceWorker()`: Auto-registers `/sw.js` with root scope.
  - `requestNotificationPermission()`: Interactive prompt handler.
  - `showBrowserNotification()`: Dual-path fallback supporting Service Worker notifications with Window Notification API fallback.
  - `sendTestPushNotification()`: Interactive test trigger with custom badge.
  - `checkAndTriggerDueAlerts()`: Automated evaluation engine that triggers alerts for:
    1. **Upcoming Bills:** Pending bills due in $\le 3$ days (or custom threshold).
    2. **Budget Threshold Warnings:** Budgets that have reached or exceeded the set threshold ($\ge 80\%$).
- **UI Integration:**
  - **Dashboard (`src/pages/Dashboard.jsx`):** Automatically evaluates due bills and budget limits on load; displays an interactive 1-click "Enable Alerts" card in `NotificationsBanner.jsx` when permission is unprompted.
  - **Settings (`src/pages/Settings.jsx`):** Dedicated "Browser Push Notifications" card with live permission status pill, one-click enablement, and a "Send Test Push" button.
  - **Header & Mobile Header (`src/Layout.jsx`):** Quick notification bell button with active status indicator.

## 4. SimpleWebAuthn Biometrics Architecture
Engineered per the user request using `@simplewebauthn/browser` and `@simplewebauthn/server`:
- **Hardware Integration:**
  - Automatic detection of biometric support via `checkBiometricsSupport()` (`browserSupportsWebAuthn` and `platformAuthenticatorIsAvailable`).
  - Native hardware enclave integration for Face ID, Touch ID, Windows Hello, and Android Biometrics.
- **Registration Flow:**
  - `POST /api/webauthn/registration-options`: Generates challenge, RP details (`Fuloozi Household Ledger`), and cryptographic public key parameters via `@simplewebauthn/server`.
  - Client prompts native Touch ID / Face ID sheet via `startRegistration({ optionsJSON })`.
  - `POST /api/webauthn/verify-registration`: Validates attestation response and stores credential ID, public key, counter, and friendly device name.
- **Authentication Flow:**
  - One-tap "Sign in with Face ID / Touch ID" on the Sign In screen.
  - Native biometric prompt signs the server challenge.
  - On verification, creates authenticated session and opens ledger instantly without typing.
  - Seamless fallback to 4-digit MPIN always available.
- **Settings Management:**
  - Device Passkeys card in Settings with enrollment status, hardware badges, and credential deletion.

## 7. Fix Pass: `npm run dev` audit (2026-11-15, Claude Code)
Starting point: commit `4eda6cb`. The dev server started cleanly and every page rendered, but the audit found the bugs below. All fixes are uncommitted in the working tree.

**Fixed**
1. **Hardcoded Kapso API key removed** (`server/kapsoAgent.js`). The key and phone-number ID were committed as fallbacks in unpushed commit `b8745ae`, and the GitHub repo is public. Credentials are now read at call time from the environment, and a clear "not configured" status is returned when they are missing.
2. **`.env.local` now reaches the dev API** (`vite.config.js`). Vite only exposed it to client code, so the Node middleware silently used the hardcoded key. It now loads env files into `process.env`; variables already set in the shell still take priority.
3. **Passkey sign-in no longer accepts everything** (`server/webauthnService.js`). Before the fix, unknown credentials, forged signatures, made-up or replayed challenges and other users' passkeys all signed in, because `@simplewebauthn/server` v14 expects `credential:` (the code passed the v9 `authenticator:`) and failures were swallowed. Challenges are now server-issued, single-use, typed and expire after 5 minutes.
4. **WhatsApp linking regression reverted** (`src/pages/Assistant.jsx`, `src/components/settings/WhatsAppConnection.jsx`). Commit `0b5f348` replaced each user's pairing code with the mock `7829104921`. "Chat on WhatsApp", "Open in WhatsApp" and "Copy link" now use `opus_open_whatsapp()` again. The bot number comes from `VITE_WHATSAPP_NUMBER`.
5. **WhatsApp status badge tells the truth.** It started as "Verified & Active" and stayed that way when the status check failed. It now shows Checking / Verified / Not Connected, with the error message.
6. **Sign-out sticks in dev mode** (`src/api/client.js`). Before, a reload signed you back in as the demo owner.
7. **Budget push alerts use this month's spending** (`src/utils/notifications.js`). They summed all-time spending, so a monthly budget eventually showed as permanently "exceeded". The rule now matches the Dashboard and Budgets pages.
8. **Bills require a due date** (`TransactionForm.jsx`, bill mode). Bills saved without one were confirmed with a toast and then never listed.
9. **Lint and console cleaned up:** ESLint went from 10 errors and 1 warning to 0, and the React Router v7 future-flag warnings are gone (opted in on `BrowserRouter`).

**Verified**

## 8. Production passkeys on Supabase + Vercel (2026-11-15, Claude Code)
Branch `claude/great-almeida-1509b6`, on top of `aaa3e26`. This replaces the "Production passkey sign-in" pending item in section 7.

**Done**
1. **Storage in Supabase** (`supabase/migrations/202611150007_passkeys.sql`): `opus_passkeys` and `opus_passkey_challenges`, both with RLS. Members can read and delete their own passkeys. Only the server (secret key) can enroll, update counters or touch challenges. Challenges are consumed with `DELETE ... RETURNING`, so each one works once.
2. **Enrollment needs a real session**: `registration-options` and `verify-registration` check the caller's access token with Supabase Auth (`auth.getUser`). The account comes from the token, never from the request body.
3. **Real sessions at sign-in**: after the signature checks out, the server generates a one-time magic-link token (`auth.admin.generateLink`, no email is sent) and exchanges it with `verifyOtp` on a throwaway client. `App.jsx` gets real `access_token`/`refresh_token` values for `setSession`.
4. **One code path**: `api/webauthn.js` and the Vite dev API both call `handleWebAuthnRequest` in `server/webauthnService.js`. With no Supabase variables (and not on Vercel), the JSON-file dev mock still works. A deployment missing the secret key returns 503 rather than falling back to the mock.
5. **Vercel routing**: `/api/webauthn/:action` 404'd on Vercel because `api/webauthn.js` only serves `/api/webauthn`. `vercel.json` now rewrites it.
6. **Admin page**: the passkey list and Revoke button read and delete `opus_passkeys` (the account's passkeys, not this browser's localStorage). "Test Sensor" verifies the signed-in user's own passkey without creating a new session.
7. Kept from section 7: server-issued, typed, single-use five-minute challenges; unknown credentials rejected; the v14 `credential:` parameter. Counter updates are compare-and-set, so a passkey revoked mid-sign-in fails closed.
